Runs on Windows and macOS

The kill switch did not exist on a Mac
It matched raw key codes, and those are not portable: q is 81 on Windows, 12 on macOS, 113 under X11. So Ctrl+Alt+Q could never fire on a Mac — and failed silently, which is worse than not running there at all, because you would trust it. Modifiers now match pynput's Key members, which are identical on every platform; only the letter needs a per-OS table. Reverting that table to the old hardcoded 81 makes the test fail, so it catches the real bug rather than just passing.
Play/pause silently did nothing on macOS
playpause isn't in pyautogui's macOS key table at all, and its _keyDown just returns for a key it doesn't know — no exception. So the action reported success in 0 ms having sent nothing. Both media keys now go out as NSSystemDefined events through pyautogui's own _specialKeyEvent.
Zoom, screens and serial ports all differ
Zoom's global mute is Cmd+Shift+A on macOS, not Alt+A. Native -fullscreen there animates for half a second and moves the blank into its own Space, missing the "covers in under a second" bar. And the board is /dev/cu.usbmodem…, not COM4 — now auto-detected. One caveat that is macOS's, not ours: Accessibility and Input Monitoring must both be granted, and neither library complains when they aren't.

Three defects found and fixed

The first thumbs-up would have frozen gesture recognition
led_beat_start ran a Tk mainloop on whichever thread called it — so the moment Nicholas's loop fired it, that loop would have stopped and no further gesture would ever be recognised. Windows now live on one shared UI thread and every action returns immediately; measured at 10 ms.
Two Tk roots in one process
The privacy blank and the beat dot each built their own. That's undefined behaviour, and it only bites when both features are used in the same run — which is exactly what the 90-second demo does. One root now, owned by one thread.
The stillness metric disagreed with itself across machines
It accumulated the torso's path length, which grows with sample rate: identical stillness read 0.008 at 15 fps and 0.032 at 60 fps against a fixed 0.05 threshold, so the dev laptop and the demo laptop would have disagreed about whether anyone was moving. Now measures how far the shoulder–hip midpoint strays from its own windowed average — 0.0004 at every frame rate tested.

Still needs a person

  • Enable Zoom's global mute shortcut — Settings → Keyboard Shortcuts → Mute/Unmute My Audio → tick Enable Global Shortcut. Two minutes, and without it Alt+A only works when Zoom is already focused, which is the one case that doesn't matter.
  • Run the phone test — join a meeting from your phone, minimise Zoom, fire mute_toggle five times each way, watch the indicator.
  • Confirm a board and an LED are on the table. If not, the LED half drops and the screen dot carries it — that path is already tested.
  • On a Mac, grant Accessibility and Input Monitoring to your terminal in System Settings → Privacy & Security, then quit and reopen it. Neither library raises without them — they just quietly do nothing, which looks exactly like a bug in this code.
  • Finish moving Track B into Nicholas's repo. His trunk is master, and a stray track-b branch there currently holds a commit from an unrelated project — delete it, push the real branch from a clone of this repo, and open the pull request so he can review the safety.py change. Steps are in COLLABORATING.md.
